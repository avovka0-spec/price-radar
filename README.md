# ЦенРадар — PWA-трекер цен на iPhone

Отслеживание цен товаров **Wildberries** по ссылке: график динамики до **180 дней**,
статистика (мин/сред/макс за 30 дней), push-уведомления при изменении цены
(**Web Push** на iPhone, iOS 16.4+), целевая цена / порог изменения в % и
**ручной ввод цены** (полая точка на графике — как в xmix.pro, когда Actions-авточка
не пытается дублировать: например, цена на Ozon-товар в ручном режиме или при самовывозе).

## Архитектура (без своего сервера)

```
iPhone (Safari → PWA «На экран Домой»)
   │  добавляет товар, коммитит data/products.json через GitHub API
   ▼
GitHub репозиторий  ──►  GitHub Pages (статический Next.js, этот сайт — само приложение)
   │
   └─► GitHub Actions (каждые 2 ч):
        • WB открытый API: card.wb.ru/cards/v2/detail?...&nm={артикул}
        • дописывает точку цены в public/data/history.json (хранит 180 дней)
        • проверяет порог % и целевую цену
        • рассылает Web Push всем подпискам (public/data/push-subscriptions.json)
        • коммитит обновлённые public/data/*.json
```

Ограничение, как у всех аналогов (xmis и др.): история считается **с момента добавления** товара —
ретроспективные цены WB по ссылке не отдаёт.

## Запуск (шаги)

1. **Создайте репозиторий** (или используйте этот) и загрузите проект.
2. **Локальная проверка:** `npm i` → `npm run icons` (генерирует иконки в `public/icons`) → коммит и push.
3. **GitHub-токен для приложения.** GitHub → Settings → Developer settings → *Fine-grained personal access tokens*:
   - Repository access: только ваш репозиторий;
   - Permissions: **Contents: Read and write**.
   Токен вводится в приложении на iPhone (хранится только в localStorage устройства).
4. **VAPID-ключи:** локально `npm run vapid` → скрипт напечатает ключи и впишет публичный в `public/data/config.json`.
   Секреты `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (опц.) добавьте:
   Settings → Secrets and variables → Actions.
5. **Pages:** Settings → Pages → Source: **GitHub Actions** (деплой кружит workflow `deploy-pages`).
   Включите Actions (по умолчанию включены).
6. Откройте `https://<user>.github.io/<repo>/` в Safari на iPhone → «Поделиться» → **На экран «Домой»**.
7. В приложении: ⚙️ Настройки → введите owner/repo/ветку/токен → «Включить push-уведомления».

> Для просмотра интерфейса без настройки откройте сайт с параметром **`?demo`** — синтетические товары с историей за 180 дней.

## IDE багфиксы

- `npm run dev` — локальная разработка, `npm run build` (экспорт в `out/`).
- WB-бакеты картинок могут меняться → при пропавшей картинке товар продолжит считаться (картинка просто скрывается).
- Если WB изменит API `card.wb.ru` — правьте `lib/wb.ts` и `scripts/check-prices.mjs` (один формат в обоих местах).
- **WB блокирует зарубежные IP (403)** — Actions-раннеры могут не пройти. Тогда задайте секрет
  `WB_PROXY_URL` — URL вашего мини-relay с российским IP (любой RU VPS, даже самый дешёвый,
  ответ формата `{"data":{"products":[{"name","brand","salePriceU"}]}}`; скрипт добавит `?nm={артикул}`).
  С ноутбука в РФ и из Safari на iPhone API WB доступен без прокси.
- Расписание проверки: правьте cron в `.github/workflows/check-prices.yml` (на бесплатном тарифе — не чаще раза в ~2 часа).
- Токен в localStorage — риски минимальные (fine-grained, только contents одного репо), но не используйте классический broad-scope token.

## Дорожная карта (по приоритету)

1. **Ozon** — ссылку и артикул научимся парсить сразу; цены — через прокси-пул или расширение «Поделиться», т.к. антибот.
2. **Яндекс Маркет** — аналогично Ozon.
3. Push по Telegram-боту как второй канал.
4. Сравнение одинаковых товаров (дубли артикулов).


## Хранение истории и очистка

- Как хранится история проверок цен, сколько места занимает при 100+ товарах и где лежат данные: [docs/STORAGE_AND_CLEANUP.md](docs/STORAGE_AND_CLEANUP.md)
- Локальная очистка мусора (логи, кэши браузерного профиля, артефакты сборки): `npm run cleanup` (сухой прогон), `npm run cleanup -- --apply` (удалить).
- Промежуточные GitHub Issues/задачи/версии: успешные telegram-задачи watcher закрывает автоматически; остальное (старые workflow runs, releases/tags, массовое удаление issues) чистится вручную в GitHub — детали в [docs/STORAGE_AND_CLEANUP.md](docs/STORAGE_AND_CLEANUP.md).

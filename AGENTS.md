# AGENTS.md — правила для агента в репозитории price-radar

## Статусы выполнения задач в Telegram

Владелец получает статусы через бота **@opencodeOtchetBot**. Отправляй их сам, через
ретранслятор GitHub Actions:

```bash
node scripts/notify-telegram.mjs "🚀 Начал: <кратко задача>"
node scripts/notify-telegram.mjs "⏳ Этап: <что сделано / что дальше>"
node scripts/notify-telegram.mjs "✅ Готово: <итог, коммит, ссылка>"
node scripts/notify-telegram.mjs "❌ Ошибка: <что не получилось и что нужно>"
```

Обязательный минимум:

1. **Перед началом работы** — статус «начал» с формулировкой задачи.
2. **По завершении** — статус «готово» с итогом (что изменено, commit/hash, ссылка на Issue/PR).
3. **При ошибке** — статус «ошибка» с причиной и следующим шагом.
4. **Долгая задача (>10–15 минут)** — промежуточный статус на смене этапа.

Требования к сообщениям:

- 1–5 строк, по делу, на русском.
- Без токенов, паролей и содержимого `.env`.
- Если отправка не удалась (нет `GH_TOKEN`, 403 и т.п.) — не блокируй основную задачу:
  выполни её и укажи в ответе, что статус отправить не удалось.
- Не отправляй больше 5–6 сообщений на одну небольшую задачу, чтобы не спамить.

Скрипт читает `GH_TOKEN` из окружения или из `.env` в корне репозитория
(см. `.env.example`). Токену нужны scopes `repo` и `workflow`; fallback —
`repository_dispatch`, которому достаточно `repo`.

## Задачи из Telegram

Telegram → Cloudflare Worker создаёт Issues с меткой `telegram-task`.

**Автоматический режим (домашний ПК):** `scripts/opencode-issues-watcher.mjs` по
расписанию Windows Task Scheduler опрашивает открытые Issues с этой меткой, запускает
`opencode-cli run --auto` для самой старой необработанной задачи, отправляет статусы
в Telegram, комментирует и закрывает Issue после успеха. Состояние/дедупликация —
`.local/opencode-issues.json`, логи — `logs/opencode-issue-<N>.log`. ПК должен быть
включён и пользователь залогинен; модель можно задать `OPENCODE_ISSUES_MODEL`.

**Ручной режим:** если просят «выполни задачи из Issues» — бери открытые Issues с меткой
`telegram-task`, начиная с самой старой. После выполнения закоммить изменения, запушь
и отправь статус «готово» со ссылкой на Issue.
